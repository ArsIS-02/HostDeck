# Что значит каждая проверка

Справочник по проверкам HostDeck: что проверяется, чем опасно отклонение и как исправить. Тексты те же, что в карточке хоста (значок «?» у проверки); команды выполняются на самом хосте с правами администратора.

**Статусы.** `ok` — норма; `warn` — предупреждение; `fail` — ошибка; `unknown` — агент не смог определить; `info` — сведения (в том числе предупреждение, смягчённое профилем хоста); `na` — к этой системе не относится. Для общего индекса: ok = 1, warn = 0,5, fail = 0; info, na, unknown, исключения и смягчённые проверки в расчёт не входят. Подробнее о профилях и исключениях — в README и docs/lab-notes.md.

## macOS

### Disk encryption (FileVault) (`filevault`)

FileVault шифрует весь диск. Без пароля пользователя данные нельзя прочитать, даже вынув накопитель.

**Чем опасно.** При потере или краже Mac содержимое диска доступно любому, у кого есть физический доступ.

**Как исправить.**

- Системные настройки → Конфиденциальность и безопасность → FileVault → «Включить». Обязательно сохраните ключ восстановления в надёжном месте.
- Шифрование идёт в фоне, пока Mac работает.

```sh
sudo fdesetup enable
```

### SIP (system integrity) (`sip`)

SIP (System Integrity Protection) не даёт менять системные файлы и процессы даже root-у.

**Чем опасно.** Отключённая защита позволяет вредоносной программе с правами root внедриться в систему.

**Как исправить.**

- Перезагрузитесь в режим восстановления (Apple silicon: зажмите кнопку питания, «Параметры»; Intel: Cmd+R), откройте Утилиты → Терминал и выполните команду ниже, затем перезагрузитесь.

```sh
csrutil enable
```

### Gatekeeper (`gatekeeper`)

Gatekeeper проверяет подпись и нотаризацию программ, скачанных из интернета, прежде чем их запустить.

**Чем опасно.** Выключенный Gatekeeper разрешает запуск любых неподписанных программ без предупреждения.

**Как исправить.**

- Системные настройки → Конфиденциальность и безопасность → «Разрешить программы из»: App Store или App Store и проверенных разработчиков.

```sh
sudo spctl --global-enable
```

```sh
sudo spctl --master-enable   # для macOS 14 и старше
```

### Firewall (`firewall`)

Встроенный брандмауэр macOS. Он решает, каким программам разрешены входящие сетевые подключения.

**Чем опасно.** Без брандмауэра любая программа, слушающая порт, доступна из локальной сети (общий Wi-Fi, гостевая сеть, VPN).

**Как исправить.**

- Системные настройки → Сеть → Брандмауэр → включить (в macOS 12 и старше: Конфиденциальность и безопасность → Брандмауэр).

```sh
sudo /usr/libexec/ApplicationFirewall/socketfilterfw --setglobalstate on
```

### Stealth mode (`stealth`)

«Режим невидимки» — опция брандмауэра. Включённый, он заставляет Mac молчать в ответ на ping (ICMP) и на попытки подключиться к закрытым портам, поэтому сканеры портов и случайные «стуки» в сеть не видят, что хост вообще есть.

**Чем опасно.** Выключенный режим — это не поломка, а компромисс: Mac отвечает на ping и сканирование. Для ноутбука в чужой Wi-Fi лучше включить. Для сервера, который вы пингуете системой мониторинга, режим оставляют выключенным, иначе ping-проверки покажут «недоступен».

**Как исправить.**

- Системные настройки → Сеть → Брандмауэр → Параметры… → «Включить режим невидимки». Работает, только если включён сам брандмауэр.

```sh
sudo /usr/libexec/ApplicationFirewall/socketfilterfw --setstealthmode on
```

### Automatic update check (`auto_check`)

Автоматическая проверка обновлений: macOS сама сверяется с серверами Apple.

**Чем опасно.** «По умолчанию (включено)» означает, что параметр не записан в настройках: пока вы его не меняли, macOS использует значение по умолчанию — включено. «Выключено» — настоящая проблема: об обновлениях вы узнаете только вручную.

**Как исправить.**

- Системные настройки → Основные → Обновление ПО → кнопка (i) у «Автоматические обновления» → «Проверять наличие обновлений».

```sh
sudo defaults write /Library/Preferences/com.apple.SoftwareUpdate AutomaticCheckEnabled -bool true
```

### Automatic security updates (`auto_critical`)

Автоматическая установка файлов безопасности и срочных исправлений («Быстрые меры безопасности»).

**Чем опасно.** Срочные исправления уязвимостей придут с задержкой, пока вы не поставите их вручную.

**Как исправить.**

- Системные настройки → Основные → Обновление ПО → (i) → «Устанавливать файлы данных системы и обновления безопасности».

```sh
sudo defaults write /Library/Preferences/com.apple.SoftwareUpdate CriticalUpdateInstall -bool true
```

### macOS updates (`updates`)

Есть ли для Mac непоставленные обновления macOS и программ Apple. Проверку агент запускает в фоне, она может идти несколько минут.

**Чем опасно.** Пока обновления не установлены, известные уязвимости остаются открытыми. «Проверка выполняется» — просто подождите. «Не удалось» — Mac не достучался до серверов Apple (сеть, DNS, прокси); подсказка обновится при следующем опросе.

**Как исправить.**

- Системные настройки → Основные → Обновление ПО → «Обновить».
- Список ожидающих обновлений указан в подробностях карточки.

```sh
sudo softwareupdate -i -a
```

### Screen lock (`screenlock`)

Через сколько после засыпания или заставки экран блокируется и требует пароль.

**Чем опасно.** Если пароль не требуется сразу, любой, кто подошёл к оставленному Mac, получает доступ к сессии.

**Как исправить.**

- Системные настройки → Экран блокировки → «Запрашивать пароль после начала заставки или выключения дисплея» → «Сразу».

### Remote login (SSH) (`ssh`)

Удалённый вход (SSH) позволяет подключаться к Mac по сети из терминала.

**Чем опасно.** Это справочная отметка, а не ошибка. Включённый SSH нужен администратору, но расширяет поверхность атаки: ограничьте доступ нужными пользователями и входите по ключам.

**Как исправить.**

- Не нужен — отключите: Системные настройки → Основные → Общий доступ → «Удалённый вход».
- Нужен — оставьте включённым и в том же окне («i») ограничьте список пользователей.

```sh
sudo systemsetup -setremotelogin off
```

### MDM enrollment (`mdm`)

Управляется ли Mac через MDM (централизованное управление устройствами организации).

**Чем опасно.** Это справочная отметка. Для домашнего Mac без MDM «не зарегистрирован» — нормально.

### Free disk space (`disk`)

Сколько места занято на системном диске. Предупреждение с 85%, ошибка с 95%.

**Чем опасно.** Когда диск почти полон, macOS замедляется, не может ставить обновления и создавать снимки Time Machine, а приложения теряют данные при записи.

**Как исправить.**

- Системные настройки → Основные → Хранилище: освободите место рекомендациями macOS.
- Найдите самые тяжёлые каталоги командой ниже и удалите ненужное (старые образы, кэши, загрузки).
- Локальные снимки Time Machine: tmutil listlocalsnapshots /

```sh
du -xhd1 /Users | sort -h | tail -15
```

### Platform (`platform`)

Для этой операционной системы агент собирает только базовые данные и метрики. Проверки безопасности macOS здесь не применяются.

**Чем опасно.** 

### Backup (Time Machine) (`timemachine`)

Когда Time Machine в последний раз сделал резервную копию. Время берётся из настроек Time Machine. Копия не старше 7 дней — норма, старше 7 дней — предупреждение, старше 30 дней — ошибка.

**Чем опасно.** Без свежей копии потеря диска, шифровальщик или случайное удаление означают потерю данных. Если на этом Mac нет ничего ценного или копии делаются другим способом, проверку можно считать неприменимой.

**Как исправить.**

- Подключите диск для копий (если он внешний) и откройте Системные настройки → Основные → Time Machine → добавьте диск назначения.
- Проверьте, что автоматическое резервное копирование включено.

```sh
tmutil destinationinfo
sudo tmutil setdestination /Volumes/ИМЯ_ДИСКА
```

```sh
sudo tmutil startbackup
```

### Guest login (`guest`)

Гостевой пользователь: любой может войти в Mac без пароля во временную учётную запись.

**Чем опасно.** Тот, кто сел за Mac, получает рабочий стол, браузер и доступ в вашу сеть. Гостю не видны файлы других пользователей, но он может запускать программы и выходить в интернет от имени вашего адреса.

**Как исправить.**

- Системные настройки → Пользователи и группы → «Гостевой пользователь» → выключить.

```sh
sudo sysadminctl -guestAccount off
```

### Automatic login (`autologin`)

Автоматический вход: после включения Mac сам входит в учётную запись без ввода пароля.

**Чем опасно.** Любой, кто включил Mac, получает все данные этого пользователя. При включённом FileVault автоматический вход вообще недоступен. Для Mac mini, который работает как сервер без экрана, это осознанный компромисс.

**Как исправить.**

- Системные настройки → Пользователи и группы → «Автоматический вход» → «Выкл.».

```sh
sudo defaults delete /Library/Preferences/com.apple.loginwindow autoLoginUser
```

### Administrators (`admins`)

Сколько пользователей входит в группу администраторов (root и служебные записи не считаются). Не больше двух — норма, больше — предупреждение. Имена показаны в карточке.

**Чем опасно.** Каждый администратор может ставить программы, менять защиту и получать root. Чем их больше, тем больше учётных записей, взлом любой из которых отдаёт хост целиком.

**Как исправить.**

- Оставьте администраторами одну-две записи, а для повседневной работы заведите обычного пользователя.
- Лишнего администратора можно понизить в Системные настройки → Пользователи и группы.

```sh
dscl . -read /Groups/admin GroupMembership
```

```sh
sudo dseditgroup -o edit -d ИМЯ -t user admin   # убрать из администраторов
```

### Screen sharing (`sharing_screen`)

Общий доступ к экрану (Screen Sharing, протокол VNC): другие компьютеры могут смотреть на экран и управлять им.

**Чем опасно.** Это удалённый доступ к рабочему столу, защищённый только паролем пользователя. Если он не нужен, это лишняя дверь в Mac. Если вы управляете Mac так намеренно, оставьте включённым и ограничьте доступ нужными пользователями.

**Как исправить.**

- Системные настройки → Основные → Общий доступ → «Демонстрация экрана» → выключить.

```sh
sudo launchctl unload -w /System/Library/LaunchDaemons/com.apple.screensharing.plist
```

### File sharing (`sharing_files`)

Общий доступ к файлам (SMB): выбранные папки доступны по сети другим компьютерам.

**Чем опасно.** Открытый SMB — частая цель подбора паролей и эксплуатации уязвимостей в локальной сети. Включайте, только если Mac действительно раздаёт файлы.

**Как исправить.**

- Системные настройки → Основные → Общий доступ → «Общий доступ к файлам» → выключить.

```sh
sudo launchctl unload -w /System/Library/LaunchDaemons/com.apple.smbd.plist
```

### Remote management (`sharing_remote`)

Удалённое управление (Apple Remote Desktop): администратор может управлять Mac с другого компьютера. Признак — запущенный процесс ARDAgent; у macOS нет единого флага, поэтому это эвристика.

**Чем опасно.** Даёт широкие права на хосте тому, кто знает пароль. Нужно только если Mac управляется через Apple Remote Desktop или MDM.

**Как исправить.**

- Системные настройки → Основные → Общий доступ → «Удалённое управление» → выключить.

```sh
sudo /System/Library/CoreServices/RemoteManagement/ARDAgent.app/Contents/Resources/kickstart -deactivate -stop
```

### AirDrop (`airdrop`)

Кто может обнаружить Mac по AirDrop: никто, только контакты или все. Настройка читается у пользователя, который сидит за Mac.

**Чем опасно.** «Все» позволяет любому поблизости присылать вам файлы и видеть имя Mac. На публичных местах это канал для нежелательных файлов.

**Как исправить.**

- Finder → AirDrop → «Разрешить обнаружение» → «Только контакты» или «Никто».

```sh
defaults write com.apple.sharingd DiscoverableMode -string "Contacts Only"   # от имени пользователя, не sudo
```

### XProtect signatures (`xprotect`)

Насколько свежи антивирусные сигнатуры самой macOS (XProtect). Apple обновляет их отдельно от системы. Возраст определяется по дате файлов набора: до 30 дней — норма, до 90 — предупреждение, больше — ошибка.

**Чем опасно.** Устаревший набор не знает о новых вредоносных программах, и Gatekeeper пропустит их.

**Как исправить.**

- Системные настройки → Основные → Обновление ПО → ⓘ рядом с автообновлением → включить «Установка файлов данных системы и обновлений безопасности».
- Mac должен бывать в сети и не быть заблокированным фаерволом к серверам Apple.

```sh
sudo defaults write /Library/Preferences/com.apple.SoftwareUpdate ConfigDataInstall -bool true
```

```sh
sudo softwareupdate --background
```

### Configuration profiles (`profiles`)

Какие профили конфигурации установлены на Mac: MDM, Wi-Fi, сертификаты, ограничения. Для справки: профили могут менять настройки защиты и добавлять доверенные сертификаты.

**Чем опасно.** Незнакомый профиль — повод разобраться: через него можно подменить сертификаты или ограничить систему. Свои профили (например, от MDM) ожидаемы.

**Как исправить.**

- Системные настройки → Основные → Управление устройством: посмотрите, откуда профиль и нужен ли он.

```sh
sudo profiles list
sudo profiles show
```

### System extensions (`sysext`)

Какие системные расширения активны: антивирусы, EDR, VPN, виртуализация и другие программы с доступом к системе на низком уровне.

**Чем опасно.** Расширение работает с высокими правами. Незнакомое — повод проверить, какая программа его поставила.

**Как исправить.**

- Системные настройки → Основные → Объекты входа и расширения, раздел расширений. Лишнее удаляется вместе с программой.

```sh
systemextensionsctl list
```

### Display sleep (`display_sleep`)

Через сколько минут простоя гаснет дисплей. До 15 минут — норма; «Никогда» или больше 15 минут — предупреждение.

**Чем опасно.** Включённый экран без блокировки виден всем рядом и остаётся рабочим местом для любого, кто подошёл. Для Mac mini без монитора настройка не важна.

**Как исправить.**

- Системные настройки → Экран блокировки → «Выключать дисплей при питании от сети» → выберите время до 15 минут.

```sh
sudo pmset -a displaysleep 10
```

### Screen saver (`screensaver`)

Через сколько простоя запускается заставка (у пользователя за экраном). До 20 минут — норма. Вместе с проверкой «Блокировка экрана» определяет, как быстро Mac закроется паролем.

**Чем опасно.** Без заставки и пароля оставленный Mac остаётся открытым. «Не задано» — пользователь не менял настройку, действует умолчание системы.

**Как исправить.**

- Системные настройки → Экран блокировки → «Запускать заставку при неактивности» → до 20 минут, и «Требовать пароль» (см. «Блокировка экрана»).

```sh
defaults -currentHost write com.apple.screensaver idleTime -int 600   # от имени пользователя, не sudo
```

### Signed system volume (`ssv`)

Подписанный системный том (Signed System Volume): защита системного раздела macOS от подмены. Проверяется командой csrutil authenticated-root status.

**Чем опасно.** Если защита выключена, содержимое системного раздела можно изменить, и macOS не заметит подмены при запуске. Включается только из режима восстановления.

**Как исправить.**

- Перезагрузитесь в режим восстановления (на Apple Silicon: удерживайте кнопку питания), откройте Терминал из меню «Утилиты» и выполните команду.

```sh
csrutil authenticated-root enable   # выполняется в режиме восстановления
```

### Update channel (`update_channel`)

Канал, из которого Mac получает обновления (каталог Software Update). В адресе есть «seed»: Mac подписан на бета-версии macOS.

**Чем опасно.** Бета-версии нестабильны и могут содержать ошибки, а некоторые приложения на них не работают. Для рабочего Mac лучше обычный канал.

**Как исправить.**

- Отключите бета-обновления: Системные настройки → Основные → Обновление ПО → значок (i) у «Бета-обновления» → «Выкл.». Или сбросьте каталог командой ниже.

```sh
sudo softwareupdate --clear-catalog
defaults read /Library/Preferences/com.apple.SoftwareUpdate CatalogURL
```

### Network time (`net_time`)

Синхронизируется ли время Mac с сервером времени (systemsetup). Неверное время ломает проверку сертификатов, Kerberos и сопоставление событий в журналах.

**Чем опасно.** Если автосинхронизация выключена, часы уходят, и сертификаты могут считаться просроченными или ещё недействительными, а журналы с разных хостов нельзя сопоставить.

**Как исправить.**

- Включите сетевое время и укажите сервер.

```sh
sudo systemsetup -setusingnetworktime on
sudo systemsetup -setnetworktimeserver time.apple.com
systemsetup -getnetworktimeserver
```

### Internet Sharing (`internet_sharing`)

Включён ли общий доступ к интернету: Mac раздаёт своё подключение другим устройствам и становится маршрутизатором.

**Чем опасно.** Включённая раздача открывает сеть для других устройств, выдаёт им адреса и может обойти ограничения вашей основной сети.

**Как исправить.**

- Выключите: Системные настройки → Основные → Общий доступ → Общий интернет.

```sh
sudo defaults read /Library/Preferences/SystemConfiguration/com.apple.nat 2>&1 | head
```

### Running network services (`net_daemons`)

Сетевые службы, которые сейчас работают на Mac: SNMP, NoMachine, telnet, FTP. Это справка: служба может быть нужна, решение за вами.

**Чем опасно.** Каждая слушающая служба расширяет поверхность атаки. Если служба не нужна, отключите её. Если нужна, добавьте исключение с причиной, и она перестанет попадать в замечания.

**Как исправить.**

- Посмотрите, что слушает порты, и отключите ненужное. Для нужных служб заведите исключение на странице хоста.

```sh
sudo lsof -nP -iTCP -sTCP:LISTEN
sudo launchctl print system/org.net-snmp.snmpd | head
```

```sh
# отключить службу (пример для SNMP)
sudo launchctl bootout system/org.net-snmp.snmpd
sudo launchctl disable system/org.net-snmp.snmpd
```

### sudo timeout (`sudo_timeout`)

Сколько минут после ввода пароля sudo не спрашивает его снова (timestamp_timeout). По умолчанию 5.

**Чем опасно.** Чем дольше окно, тем дольше открытая сессия терминала может выполнять команды администратора без пароля.

**Как исправить.**

- Задайте короткий срок отдельным файлом и проверьте синтаксис.

```sh
echo 'Defaults timestamp_timeout=5' | sudo tee /etc/sudoers.d/hostdeck-timeout
sudo chmod 440 /etc/sudoers.d/hostdeck-timeout
sudo visudo -c
```

Классический журнал аудита BSM (/etc/security/audit_control). В современных версиях macOS он по умолчанию не настроен, события пишет унифицированный журнал, поэтому отсутствие файла не недостаток.

**Чем опасно.** 

## Linux

### Accounts with UID 0 (`uid0`)

Учётные записи с идентификатором 0, кроме root. UID 0 — это полные права администратора под другим именем.

**Чем опасно.** Лишняя запись с UID 0 — типичный след взлома (скрытая «чёрная дверь»). Если вы её не создавали, считайте хост скомпрометированным: сначала разберитесь, кто и когда вошёл, потом удаляйте.

**Как исправить.**

- Выясните, кто создал запись и когда входил под ней.
- Если запись не нужна, удалите её; если нужна, поменяйте UID и используйте sudo.

```sh
awk -F: '$3==0 {print $1}' /etc/passwd
sudo lastlog -u ИМЯ
```

```sh
sudo userdel ИМЯ   # только после выяснения обстоятельств
```

### Empty passwords (`empty_pw`)

Учётные записи, у которых в /etc/shadow пустое поле пароля, то есть вход без пароля.

**Чем опасно.** Такой пользователь входит на консоль без пароля, а при PermitEmptyPasswords yes в sshd — и по сети.

**Как исправить.**

- Задайте пароль или заблокируйте запись, если ею не пользуются.

```sh
sudo awk -F: '($2=="") {print $1}' /etc/shadow
sudo passwd ИМЯ
```

```sh
sudo passwd -l ИМЯ   # заблокировать вход по паролю
```

### Passwordless sudo (`sudo_nopasswd`)

Правила sudo с NOPASSWD: они позволяют выполнять команды от root без ввода пароля. Учитываются /etc/sudoers и /etc/sudoers.d.

**Чем опасно.** Тот, кто получил сеанс такого пользователя (украденный SSH-ключ, уязвимость в программе), сразу получает root. Для служебных учётных записей автоматизации (Ansible и т. п.) это оправдано, но лучше ограничить список конкретных команд.

**Как исправить.**

- Уберите NOPASSWD, где он не нужен.
- Для автоматизации разрешайте только нужные команды вместо ALL.

```sh
sudo grep -rn NOPASSWD /etc/sudoers /etc/sudoers.d/
sudo visudo -f /etc/sudoers.d/ИМЯ_ФАЙЛА
```

### Password policy (`pw_policy`)

Политика паролей: срок их действия (PASS_MAX_DAYS в /etc/login.defs) и минимальная длина (minlen в pwquality.conf или PASS_MIN_LEN). Норма: срок не больше 365 дней и длина не меньше 8.

**Чем опасно.** Без срока и без требований к длине пароли остаются слабыми и бессрочными. Если на хосте вход только по ключам, риск ниже, но проверка всё равно отметит отсутствие политики. PASS_MAX_DAYS действует только для новых учётных записей.

**Как исправить.**

- Задайте PASS_MAX_DAYS и minlen в конфигах.
- Для существующих пользователей срок меняется отдельно командой chage.

```sh
sudo sed -i 's/^PASS_MAX_DAYS.*/PASS_MAX_DAYS 365/' /etc/login.defs
echo 'minlen = 12' | sudo tee -a /etc/security/pwquality.conf
```

```sh
sudo chage -M 365 ИМЯ   # для существующей записи
```

### Open ports (`ports`)

Какие программы слушают порты на внешних адресах (loopback не считается). Пока вы не задали список разрешённых портов, проверка только показывает, что открыто. Когда список задан, любой другой порт считается лишним.

**Чем опасно.** Каждый открытый порт — поверхность атаки. Неожиданный порт — либо забытая служба, либо чужая программа.

**Как исправить.**

- Выясните, какая программа слушает лишний порт, и остановите её или закройте порт брандмауэром.
- Чтобы задать разрешённые порты, добавьте в /etc/hostdeck/agent.json строку "allowed_ports": [22, 443] и перезапустите агента.

```sh
sudo ss -tulnp
```

```sh
sudo nano /etc/hostdeck/agent.json   # "allowed_ports": [22, 443]
sudo systemctl restart hostdeck-agent
```

### Kernel hardening (`sysctl`)

Защитные параметры ядра: рандомизация адресов (ASLR, randomize_va_space=2), rp_filter, SYN-cookies, запрет принимать и отправлять ICMP-перенаправления и source routing, скрытие адресов ядра (kptr_restrict) и журнала ядра (dmesg_restrict), запрет дампов памяти setuid-программ (suid_dumpable=0). В карточке показаны отклонения.

**Чем опасно.** Каждый параметр закрывает отдельный приём атаки: подмену маршрутов, спуфинг адресов, утечку адресов ядра для эксплойтов. Осторожно: rp_filter=1 ломает асимметричную маршрутизацию, а запрет перенаправлений не подходит для маршрутизаторов.

**Как исправить.**

- Создайте файл с нужными значениями и примените его. Проверьте, что сеть работает, особенно на маршрутизаторах и хостах с VPN.

```sh
sudo tee /etc/sysctl.d/90-hardening.conf <<'EOF'
kernel.randomize_va_space = 2
net.ipv4.conf.all.rp_filter = 1
net.ipv4.tcp_syncookies = 1
net.ipv4.conf.all.accept_redirects = 0
net.ipv4.conf.all.send_redirects = 0
net.ipv4.conf.all.accept_source_route = 0
kernel.kptr_restrict = 1
kernel.dmesg_restrict = 1
fs.suid_dumpable = 0
EOF
sudo sysctl --system
```

### /tmp and /var/tmp mounts (`tmp_mount`)

Как смонтированы /tmp и /var/tmp. Рекомендация (CIS): отдельные разделы или tmpfs с параметрами nosuid, nodev и noexec.

**Чем опасно.** В /tmp пишет любой пользователь и любая программа, и вредоносный код обычно запускают оттуда. Параметр noexec запрещает запуск файлов из каталога, nosuid отключает права setuid. Осторожно: noexec в /tmp может сломать установщики и программы, которые распаковывают и запускают себя оттуда. Сначала проверьте на тестовой машине.

**Как исправить.**

- Добавьте tmpfs для /tmp в /etc/fstab, а /var/tmp привяжите к нему, затем перемонтируйте.

```sh
echo 'tmpfs /tmp tmpfs defaults,nosuid,nodev,noexec,size=2G 0 0' | sudo tee -a /etc/fstab
echo '/tmp /var/tmp none bind 0 0' | sudo tee -a /etc/fstab
sudo mount -a && findmnt /tmp /var/tmp
```

### Disk health (SMART) (`smart`)

Самодиагностика дисков SMART (smartctl -H). В виртуальных машинах SMART недоступен, и проверки не будет. Нужен пакет smartmontools.

**Чем опасно.** «Отказ» значит, что диск сам считает, что скоро выйдет из строя. Срочно сделайте копию данных и замените диск.

**Как исправить.**

- Сразу скопируйте важные данные, затем замените диск.
- Подробности: smartctl -a, обратите внимание на Reallocated_Sector_Ct и Pending.

```sh
sudo smartctl -a /dev/sda
```

```sh
sudo smartctl -t short /dev/sda   # короткий тест диска
```

### Audit rules (`audit_rules`)

Загружены ли правила аудита ядра. Запущенная служба auditd без правил ничего не записывает.

**Чем опасно.** Нет правил — нет записей о входах, изменении учётных записей и конфигов, а значит и материала для расследования. Если ядро работает в режиме -e 2 (правила заперты), изменения применяются только после перезагрузки.

**Как исправить.**

- Добавьте файл с правилами в /etc/audit/rules.d и загрузите его. Ниже минимальный набор: наблюдение за учётными записями, sudo и sshd.

```sh
sudo tee /etc/audit/rules.d/hostdeck.rules <<'EOF'
-w /etc/passwd -p wa -k identity
-w /etc/shadow -p wa -k identity
-w /etc/sudoers -p wa -k sudo
-w /etc/ssh/sshd_config -p wa -k sshd
EOF
sudo augenrules --load
sudo auditctl -l
```

### Log forwarding (`log_forward`)

Отправляет ли хост журналы на другой сервер: rsyslog или syslog-ng (например, в Graylog), journal-upload, audisp-remote, либо работает агент (Wazuh, Graylog Sidecar, Filebeat, Vector, Fluent Bit и др.). Проверяется наличие настройки и работающей службы, а не доставка сообщений: что они доходят, смотрите на стороне Graylog или Wazuh.

**Чем опасно.** Взломщик первым делом чистит локальные журналы. Без копии на другом хосте расследовать инцидент нечем.

**Как исправить.**

- Для Graylog через rsyslog добавьте пересылку по TCP и перезапустите службу.
- Для Wazuh установите агент и укажите адрес менеджера.

```sh
echo '*.* @@graylog.example.lab:514' | sudo tee /etc/rsyslog.d/90-forward.conf
sudo systemctl restart rsyslog
```

```sh
logger -t hostdeck-test "проверка пересылки"   # затем найдите сообщение в Graylog
```

### Security updates (`sec_updates`)

Сколько пакетов с обновлениями именно безопасности ждут установки (по данным уведомлений в репозиториях: dnf updateinfo, apt security). Критическая уязвимость делает проверку красной. «В репозиториях нет данных о безопасности» значит, что репозитории не публикуют уведомления, и отличить обновления безопасности от прочих нельзя: ориентируйтесь на проверку «Обновления пакетов».

**Чем опасно.** Это самые срочные обновления: для таких уязвимостей обычно уже есть публичные эксплойты.

**Как исправить.**

- Установите обновления безопасности в ближайшее окно обслуживания. Если затронуто ядро или системные библиотеки, потом перезагрузитесь.

```sh
sudo dnf updateinfo list security
sudo dnf upgrade --security -y
```

```sh
sudo apt-get -s upgrade | grep -i security   # Debian, Ubuntu
sudo unattended-upgrade
```

### File integrity monitoring (`integrity`)

Работает ли контроль целостности файлов: AIDE (есть база), IMA, Tripwire или Samhain. Он запоминает контрольные суммы системных файлов и замечает подмену.

**Чем опасно.** Без него подмену системных программ (руткит) обычно замечают поздно или не замечают совсем.

**Как исправить.**

- Установите AIDE, создайте базу и запускайте проверку по расписанию (cron или systemd timer). Создание базы занимает несколько минут.

```sh
sudo dnf install -y aide   # или: sudo apt install -y aide
sudo aide --init
sudo mv /var/lib/aide/aide.db.new.gz /var/lib/aide/aide.db.gz
sudo aide --check
```

### FreeIPA domain and sssd (`freeipa`)

Включён ли хост в домен FreeIPA и работает ли sssd. Если файла /etc/ipa/default.conf нет, проверка только справочная: хост вне домена. Если домен есть, проверяются sssd, keytab хоста (/etc/krb5.keytab) и связь с доменом (sssctl domain-status).

**Чем опасно.** Хост, выпавший из домена, не принимает доменных пользователей и политики (sudo, HBAC), а пароли и ключи на нём приходится вести вручную. Домен «недоступен» чаще всего значит проблему с DNS, временем или сетью до сервера FreeIPA.

**Как исправить.**

- Перезапустите sssd и посмотрите состояние домена.
- Если keytab потерян, повторно включите хост в домен командой ipa-client-install (нужны права администратора FreeIPA).
- Проверьте синхронизацию времени: Kerberos требует расхождения не более 5 минут.

```sh
sudo systemctl status sssd
sudo systemctl restart sssd
sudo sssctl domain-list
sudo sssctl domain-status ДОМЕН
sudo klist -k /etc/krb5.keytab
```

```sh
sudo ipa-client-install --force-join   # повторное включение в домен
```

### Certificate expiry (`certs`)

Сроки действия локальных сертификатов. Просматриваются типичные каталоги: /etc/letsencrypt/live, /etc/pki/tls/certs, /etc/pki/ca-trust/source/anchors, /usr/local/share/ca-certificates, /etc/ipa, /var/lib/ipa/certs. Общие пакеты доверенных центров (ca-bundle) не считаются. В карточке показан ближайший срок. Меньше 30 дней — предупреждение, истёкший сертификат — ошибка.

**Чем опасно.** Истёкший сертификат ломает TLS, LDAPS и Kerberos/FreeIPA: службы перестают соединяться, а браузеры пугают пользователей.

**Как исправить.**

- Перевыпустите или продлите сертификат из карточки.
- Для Let's Encrypt проверьте, что продление по расписанию работает; для FreeIPA посмотрите certmonger.

```sh
sudo openssl x509 -in /путь/к/сертификату.crt -noout -subject -enddate
sudo certbot renew --dry-run
```

```sh
sudo getcert list   # certmonger, FreeIPA
```

### Firewall (`firewall`)

Менеджер брандмауэра хоста: firewalld (в RED OS и других дистрибутивах семейства RHEL) или ufw (Debian, Ubuntu). Он решает, какие входящие подключения пропускать.

**Чем опасно.** Без брандмауэра любая программа, слушающая порт, доступна из сети. Значение «Правила заданы вручную» означает, что менеджера нет, но правила iptables/nftables есть.

**Как исправить.**

- Включите службу. Перед этим убедитесь, что SSH разрешён, иначе потеряете доступ к хосту по сети.

```sh
sudo firewall-cmd --permanent --add-service=ssh
sudo systemctl enable --now firewalld
```

```sh
sudo ufw allow OpenSSH && sudo ufw enable   # для ufw
```

### iptables / nftables rules (`iptables`)

Сколько правил фильтрации загружено в ядро (iptables и nftables вместе) и какая политика у входящего трафика (INPUT). Firewalld хранит свои правила в nftables, поэтому считаются оба.

**Чем опасно.** Нет правил и политика ACCEPT — значит, ядро не фильтрует входящий трафик вообще. Политика DROP без правил, наоборот, закроет всё, включая SSH.

**Как исправить.**

- Включите брандмауэр (см. проверку «Брандмауэр») и посмотрите, что загружено.

```sh
sudo iptables -S
sudo nft list ruleset
```

```sh
sudo firewall-cmd --list-all
```

### SELinux (`selinux`)

SELinux — обязательное разграничение доступа в ядре: даже взломанная служба видит только то, что ей разрешено политикой. Режимы: Enforcing (применяется), Permissive (только пишет нарушения в журнал), Disabled (выключен).

**Чем опасно.** В режимах Permissive и Disabled политика не защищает хост. Из Disabled нельзя просто «включить на лету»: нужна перезагрузка и перемаркировка файлов, это долго на больших дисках.

**Как исправить.**

- Permissive → Enforcing: можно сразу. Перед этим посмотрите журнал: ausearch -m avc -ts recent.
- Disabled: поменяйте SELINUX в /etc/selinux/config, создайте /.autorelabel и перезагрузитесь.

```sh
sudo setenforce 1
sudo sed -i 's/^SELINUX=.*/SELINUX=enforcing/' /etc/selinux/config
```

```sh
sudo touch /.autorelabel && sudo reboot   # только если был Disabled
```

### SSH server (sshd) (`sshd`)

Настройки SSH-сервера (по выводу sshd -T): разрешён ли вход root и вход по паролю.

**Чем опасно.** Вход root по SSH и пароли — основная цель подбора паролей из интернета. «Не запущено» — справка: сервер SSH на хосте не работает.

**Как исправить.**

- Заведите ключи и проверьте вход по ним. Только потом отключайте пароли.
- В /etc/ssh/sshd_config задайте PermitRootLogin no и PasswordAuthentication no, затем проверьте конфиг и перечитайте его.

```sh
sudo sshd -t && sudo systemctl reload sshd
```

### Package updates (`pkg_updates`)

Есть ли доступные обновления пакетов (dnf в RED OS и других дистрибутивах семейства RHEL, apt в Debian и Ubuntu). Проверка идёт в фоне и может занять несколько минут.

**Чем опасно.** Пока обновления не установлены, известные уязвимости остаются открытыми. «Проверка выполняется» — просто подождите. «Не удалось» — не получен ответ от репозиториев (сеть, DNS, прокси, подписка).

**Как исправить.**

- Установите обновления в удобное время. Ядро и системные библиотеки потребуют перезагрузки (см. проверку «Перезагрузка»).

```sh
sudo dnf upgrade -y
```

```sh
sudo apt update && sudo apt upgrade -y   # Debian, Ubuntu
```

### Reboot after updates (`reboot`)

Нужна ли перезагрузка, чтобы применить обновлённые ядро или системные библиотеки.

**Чем опасно.** До перезагрузки хост продолжает работать на старом ядре с известными уязвимостями.

**Как исправить.**

- Перезагрузите хост в безопасное время. Узнать причину: needs-restarting -r (dnf) или файл /var/run/reboot-required (apt).

```sh
sudo needs-restarting -r
sudo reboot
```

### Audit (auditd) (`auditd`)

Служба аудита ядра Linux: пишет в журнал входы, изменения файлов и системные вызовы по заданным правилам.

**Чем опасно.** Без неё нет журнала для расследования инцидентов и для внешних систем (Graylog, Wazuh).

**Как исправить.**

- Включите службу и загрузите правила из /etc/audit/rules.d.

```sh
sudo systemctl enable --now auditd
sudo augenrules --load
sudo auditctl -l
```

### Time synchronization (`time_sync`)

Синхронизировано ли время хоста с сервером времени (chrony, systemd-timesyncd).

**Чем опасно.** Сбитые часы ломают TLS-сертификаты и Kerberos/FreeIPA, а метки времени в журналах перестают совпадать между хостами.

**Как исправить.**

- Включите службу времени и принудительно подстройте часы.

```sh
sudo systemctl enable --now chronyd
sudo chronyc makestep
timedatectl status
```

### Failed systemd units (`failed_units`)

Службы systemd, которые упали или не смогли запуститься. Первые названия указаны в карточке.

**Чем опасно.** Сбойная служба — это не работающая функция хоста или сигнал о проблеме.

**Как исправить.**

- Посмотрите причину в журнале, исправьте и сбросьте отметку о сбое.

```sh
systemctl --failed
sudo journalctl -u ИМЯ.service -b --no-pager | tail -50
sudo systemctl reset-failed
```

### Disk encryption (LUKS) (`luks`)

Зашифрован ли хотя бы один диск или раздел через LUKS (dm-crypt).

**Чем опасно.** Незашифрованный диск читается при физическом доступе к хосту. Для сервера в закрытом помещении это допустимый риск, для ноутбука нет. Включить шифрование на работающей системе нельзя, его планируют при установке.

**Как исправить.**

- Решение принимается при установке или переустановке: выберите шифрование диска в установщике.
- Проверить текущее состояние: lsblk -f.

```sh
lsblk -f
```

### Free disk space (`disk`)

Сколько места занято на системном диске. Предупреждение с 85%, ошибка с 95%.

**Чем опасно.** Когда диск почти полон, службы падают при записи, журналы и базы данных повреждаются, обновления не ставятся.

**Как исправить.**

- Найдите самые тяжёлые каталоги командой ниже и удалите ненужное.

### System crypto policy (`crypto_policy`)

Общая криптографическая политика системы (update-crypto-policies). Она задаёт, какие алгоритмы разрешены в sshd, TLS и других библиотеках. LEGACY оставляет SHA-1, CBC и 3DES для совместимости со старыми системами.

**Чем опасно.** В режиме LEGACY разрешены устаревшие алгоритмы, которые считаются слабыми. Для домашней сети риск небольшой, но для сервера лучше DEFAULT. Осторожно: после перехода на DEFAULT очень старые клиенты (старые ОС, сетевые устройства) могут перестать подключаться по SSH и TLS.

**Как исправить.**

- Сначала убедитесь, что нет устройств, которым нужен LEGACY, затем переключите политику и перезапустите sshd. Оставляйте вторую открытую сессию, пока не проверили вход.

```sh
update-crypto-policies --show
sudo update-crypto-policies --set DEFAULT
sudo systemctl restart sshd
```

```sh
# откат, если что-то перестало работать
sudo update-crypto-policies --set LEGACY
sudo systemctl restart sshd
```

### SSH hardening (`ssh_hardening`)

Действующая конфигурация sshd (sshd -T): включён ли X11Forwarding, число попыток входа MaxAuthTries и слабые алгоритмы (CBC, 3DES, SHA-1 в обмене ключами).

**Чем опасно.** X11Forwarding даёт удалённому графический канал к вашему экрану, на сервере он не нужен. Большое число попыток упрощает перебор паролей. Слабые алгоритмы закрываются криптополитикой системы (см. проверку «Криптополитика системы»).

**Как исправить.**

- Положите настройки в отдельный файл с именем, которое сортируется раньше основного (в sshd побеждает первое значение), проверьте конфигурацию и перечитайте её. Не закрывайте текущую сессию, пока не проверите новый вход.

```sh
sudo tee /etc/ssh/sshd_config.d/00-hostdeck.conf <<'EOF'
X11Forwarding no
MaxAuthTries 4
EOF
sudo sshd -t && sudo systemctl reload sshd
sudo sshd -T | grep -Ei 'x11forwarding|maxauthtries'
```

```sh
# слабые алгоритмы: переключите политику
sudo update-crypto-policies --set DEFAULT && sudo systemctl restart sshd
```

### Lockout after failed logins (`lockout`)

Блокируется ли учётная запись после нескольких неудачных входов (pam_faillock). Проверяются настройки PAM и файл /etc/security/faillock.conf.

**Чем опасно.** Без блокировки пароль можно подбирать без ограничений на любом сервисе, который использует PAM (SSH, консоль, sudo). Осторожно: слишком строгие значения позволяют заблокировать чужой доступ нарочно, поэтому выбирайте разумный порог и время разблокировки.

**Как исправить.**

- Включите faillock через authselect и задайте порог. Перед этим откройте вторую сессию SSH или консоль root, чтобы не потерять доступ при ошибке.

```sh
sudo authselect current
sudo authselect enable-feature with-faillock
sudo tee -a /etc/security/faillock.conf <<'EOF'
deny = 5
fail_interval = 900
unlock_time = 900
EOF
```

```sh
# разблокировать пользователя
sudo faillock --user ИМЯ --reset
sudo faillock --user ИМЯ
```

### auditd state (`audit_state`)

Работает ли подсистема аудита ядра (auditctl -s): включена ли она и теряет ли события (счётчик lost).

**Чем опасно.** Выключенный аудит не записывает ничего. «Потеряно событий» значит, что очередь переполнялась и часть записей пропала: чаще всего при пике нагрузки или слишком маленьком backlog. Счётчик растёт с момента загрузки и сам не обнуляется.

**Как исправить.**

- Если аудит выключен, включите службу. Если события теряются, увеличьте очередь (backlog) и проверьте нагрузку.

```sh
sudo systemctl enable --now auditd
sudo auditctl -s | grep -E 'enabled|lost|backlog'
```

```sh
# увеличить очередь: добавьте строку в правила и загрузите
echo '-b 16384' | sudo tee /etc/audit/rules.d/00-backlog.rules
sudo augenrules --load
sudo auditctl -s | grep backlog_limit
```

### Wazuh agent (`wazuh`)

Состояние агента Wazuh: связь с менеджером по данным wazuh-agentd.state (connected / pending / disconnected) и свежесть последнего ответа. Если ответа нет больше 10 минут, статус становится «Внимание».

**Чем опасно.** Без связи с менеджером события безопасности с этого хоста не доходят до центра мониторинга, а вы об этом не узнаете.

**Как исправить.**

- Проверьте службу и журнал агента, затем адрес менеджера и доступность его порта.

```sh
sudo systemctl status wazuh-agent --no-pager
sudo tail -n 30 /var/ossec/logs/ossec.log
sudo grep -A3 '<server>' /var/ossec/etc/ossec.conf
```

```sh
sudo systemctl restart wazuh-agent
sudo ss -tn | grep 1514   # соединение с менеджером
```

### Persistent systemd journal (`journal`)

Хранится ли журнал systemd на диске (есть каталог /var/log/journal). Без него журнал живёт в памяти и исчезает при перезагрузке.

**Чем опасно.** После сбоя или перезагрузки не останется записей о том, что происходило перед ней, а расследовать инцидент будет нечем.

**Как исправить.**

- Создайте каталог для постоянного журнала и перезапустите journald. При желании ограничьте размер.

```sh
sudo mkdir -p /var/log/journal
sudo systemd-tmpfiles --create --prefix /var/log/journal
sudo systemctl restart systemd-journald
journalctl --disk-usage
```

```sh
# ограничить размер журнала
sudo mkdir -p /etc/systemd/journald.conf.d
printf '[Journal]\nSystemMaxUse=1G\n' | sudo tee /etc/systemd/journald.conf.d/size.conf
sudo systemctl restart systemd-journald
```

### Legacy and extra services (`legacy_svc`)

Работающие устаревшие и лишние службы: telnet, rsh, rlogin, rexec, vsftpd, tftp (небезопасные, «Проблема») и cups, avahi-daemon (лишние на сервере, «Справка»).

**Чем опасно.** Telnet, rsh и FTP передают пароли открытым текстом. Cups и avahi открывают сетевые порты и расширяют поверхность атаки, а на сервере без принтеров и без обнаружения служб в сети они обычно не нужны. Осторожно: на рабочей станции с принтером отключать cups не надо.

**Как исправить.**

- Отключите ненужную службу вместе с её сокетом и убедитесь, что она больше не слушает порты.

```sh
sudo systemctl disable --now cups.service cups.socket cups.path
sudo systemctl disable --now avahi-daemon.service avahi-daemon.socket
```

```sh
sudo ss -tulpn | grep -E 'cupsd|avahi'   # после отключения вывода быть не должно
```
